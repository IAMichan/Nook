Real hands

Not just words. A workspace to actually do the work.

Every agent Nook runs, and every agent you link, gets Nook's workspace through a small local MCP server. Whatever it starts or opens shows up beside its session.

A visible terminalDev servers and watchers run in a Nook terminal you can see and take over, badged with the agent that started it.
Its own browserOpen a page, read its text and console errors, take a screenshot, click and type. Each session has its own, so agents never swap pages.
Simulators and devicesThe iOS Simulator and Android devices, with screenshots the agent can check its work against.
Pull requestsPush and open a pull request after your Allow, then watch it: failed checks, conflicts and reviews wake the agent.
Agents that delegateHand a subtask to another agent: two levels deep at most, four at a time, never with more rights. Stop the parent and its children stop too.
Scheduled tasksEvery morning, every hour, on chosen days: a task runs in a new session, proposed by the agent and started only after you approve it.
Secrets, on requestAn agent asks for a key by name and says why. On your Allow it gets the value from Nook's keychain, never shown in the timeline.
The rest of NookAgents can use Nook's own tools too: send a chat message, add an event, play music. Each action waits on the same card.
Another machineRun a session on a server over SSH, with Nook's browser and its own timeline, and nothing that acts on your Mac.

Connect

Already running agents in your terminal? Keep them there.

In Settings › Agents, Nook connects them with one click: it shows the exact change first, keeps a backup, and writes only after you confirm. To give them Nook's workspace too, click Connect in Settings › Automation, or run:

$ claude mcp add --scope user nook -- ~/.nook/nook-mcp --agent claude-code $ codex mcp add nook -- ~/.nook/nook-mcp --agent codex
ConnectOne click per agent in Settings › Agents, or the commands above for the workspace tools.
Restart the agentIts sessions appear in Nook's list right away, with what they do and what they ask.
Answer where you areIn Nook's window, on your phone, or in the notch if you turned it on. The terminal still works too.
Questions

Good to know.

Do my agents still work without Nook?

Yes. Agents talk to Nook over a local socket; when Nook is not running, the hook and the MCP server simply step aside and the agent carries on and asks you in its own way.

Which agents can I approve from Nook?

Claude Code, Codex, Copilot CLI, Muse Code, OpenCode and Hermes send their approvals to Nook. Gemini CLI, Antigravity, Cursor and Amp give a hook no way to allow a call, so they ask in their own window. In sessions Nook runs itself, every agent asks in Nook.

Can two agents work on the same repository?

Yes. Start each session in its own Git worktree on its own branch, so they never overwrite each other's work, and each gets its own browser.

Does Nook send my code anywhere?

Nook itself doesn't. Your agents talk to their own providers as they always do; Nook watches them locally and keeps its audit log on your Mac.
