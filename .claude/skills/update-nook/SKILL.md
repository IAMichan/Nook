# Updating Nook from GitHub

Work in the root directory of the Nook repository (the folder containing `apps/` and `packages/`). Reply in the language the user used in chat (defaulting to English), and always keep any git commits, branch names, or PRs in English. Be transparent about what succeeded and what failed.

Nook is a monorepo (see `docs/MONOREPO.md`):
- `apps/macos/` — the Mac app, with `project.yml` → `apps/macos/Nook.xcodeproj`
- `apps/ios/` — the iPhone companion, with `project.yml` → `apps/ios/NookCompanion.xcodeproj`
- `packages/` — shared packages across apps (e.g. `packages/protocol`, `packages/core`)
- `apps/android`, `apps/windows`, `apps/linux` — platform scaffolds (nothing to build yet)

## Steps

1. **Check current state**
   - Run `git branch --show-current` and `git status --short`.
   - If the user is not on `main`, ask whether they want to switch to `main` or merge `main` into the current branch. Never switch branches automatically when there are uncommitted changes.

2. **Fetch latest changes**
   - `git fetch origin`
   - Show incoming commits: `git log --oneline HEAD..origin/main`. If empty, report that the local branch is already up to date and skip steps 3 and 4.

3. **Protect local work**
   - If there are local modifications (`git status --short` is non-empty), stash them with a clear name first, e.g. `git stash push -u -m "pre-update-<timestamp>"`.
   - Never discard or overwrite local changes unless explicitly asked. Do not run `reset --hard`, `checkout .`, or `clean`.

4. **Merge**
   - On `main`: `git merge --ff-only origin/main`. If fast-forward fails (diverged local commits), stop and explain. Do not force a merge or rebase without approval.
   - On another branch: `git merge origin/main`.
   - Restore stashed changes with `git stash pop`. If conflicts occur, list the conflicting files, resolve only trivial/obvious ones, and ask the user otherwise.

5. **Regenerate Xcode projects**
   - The Xcode projects are not tracked in Git and are generated by XcodeGen. Regenerate them after every update (do not run `./update.sh` here since it also runs `git pull`):
     - `(cd apps/macos && xcodegen generate)`
     - `(cd apps/ios && xcodegen generate)`
   - **Legacy pre-monorepo project:** If a `Nook.xcodeproj` still exists in the repository root, it points to outdated paths ("Build input files cannot be found: …/Nook/App/…"). Inform the user and offer to remove it (`rm -rf Nook.xcodeproj`) after confirmation.

6. **Verify the build**
   - Mac: `(cd apps/macos && xcodebuild -project Nook.xcodeproj -scheme Nook -configuration Debug build 2>&1 | grep -E "error:|BUILD")`
   - If anything in `apps/ios` or `packages/protocol` changed, also verify the iOS companion: `(cd apps/ios && xcodebuild -project NookCompanion.xcodeproj -scheme NookCompanion -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build 2>&1 | grep -E "error:|BUILD")`
   - Report `BUILD SUCCEEDED` or the exact compiler errors per app.

7. **Wrap up**
   - Report the current HEAD commit (`git log --oneline -1`), key incoming commits, and whether a stash remains.
   - Remind the user to reopen `apps/macos/Nook.xcodeproj` in Xcode (quit Xcode with `⌘Q` first) and stop any running Nook instance before pressing `⌘R`.

## Notes

- Nook is a menu-bar and notch app (`LSUIElement`) without a Dock icon; look for the icon in the menu bar and notch.
- Do not push, commit, or delete branches unless the user explicitly asks.
